| 基线版本 | V1.0.0 |

## 目标

解决首次发布后的三个体验问题：浏览器标签缺少 GitGalaxy 品牌识别；不同数据规模下星图密度失衡；语言颜色图例不完整。

本版本不增加搜索筛选、推荐、账户系统、数据源或新的产品模块。

## 范围

### 1. 浏览器标签图标

**现状**：`apps/web/public/favicon.svg` 仍为 Vite 默认图标。

**方案**：

- 绘制 GitGalaxy 专属 favicon：深色轨道、发光核心与星体元素；保持在 16×16、32×32 和高分辨率标签页中清晰。
- 保持 `index.html` 使用 Vite 的公共资源路径，确保项目级 GitHub Pages 构建后路径正确。
- 不引入图片运行时依赖。

**验收**：Chrome、Firefox、Safari/WebKit 的标签页均显示 GitGalaxy 图标；GitHub Pages 路径部署后无 favicon 404。

### 2. 按数据规模保持星图密度

**现状**：Collector 为所有 Repository 使用固定半径范围（约 8–100），因此 100、1,000 与 5,000 条数据被压入同一空间，数据越多越拥挤。

**方案**：

- 保留 JSON 中按 Repository ID 生成的稳定基础坐标，避免因数据更新而重写、漂移历史坐标。
- 在前端按实际 `universe.total` 应用空间缩放，比例使用三维体积密度公式：

```text
spaceScale = (repositoryCount / 100)^(1 / 3)
```

- 以 100 条为基准；500 条约为 `1.71×`，1,000 条约为 `2.15×`，5,000 条约为 `3.68×`。星体半径不随该比例同步放大，因此单位空间内的星体密度保持接近一致。
- 同步扩展相机初始距离、最远缩放距离、视锥远裁剪面和雾化范围；选中项目时将聚焦目标转换至缩放后的空间坐标。
- 抽取单一空间变换工具，禁止各组件自行计算比例。

**验收**：

- 100、1,000、5,000 条数据在相同世界空间尺度下的视觉密度接近一致。
- 搜索、点击、悬停、聚焦与重置视角仍定位到正确的星体。
- `universe.json` 中已有 Repository 的原始坐标保持不变。
- 5,000 条数据下不发生远裁剪、相机无法复位或明显交互回归。

### 3. 完整语言颜色图例

**现状**：右下角图例在 `App.tsx` 中写死为 TypeScript、JavaScript 和 Python；Collector 虽已支持更多语言，界面未展示它们。

**方案**：

- 新建 `LanguageLegend` 组件，从当前加载的 Universe 数据动态聚合语言、数量和实际星体颜色。
- 扩展 Collector 的语言配色：已知语言使用固定品牌色；未预设语言从语言名称确定性生成可读颜色，避免全部落入同一种灰色 “Other”。
- 图例按数据量降序排列。默认展示主要语言；通过“全部语言”展开面板列出每一种语言和项目数量，确保所有已收录语言都有可查颜色标识。
- 在窄屏默认折叠，避免遮挡主要操作区域；不加入语言筛选，仍保持 V1.0 的探索范围。

**验收**：

- 所有有主要语言字段的 Repository 均能在展开图例中找到对应语言与颜色。
- 无主要语言的项目以单独的 “Other” 项展示。
- 图例颜色与相应星体颜色一致；桌面和移动端不遮挡搜索、详情和画质控制。

## 实施顺序

1. 新增空间缩放工具及单元测试，接入渲染和相机控制。
2. 改造 Collector 配色与动态语言图例，补充组件/数据测试。
3. 替换 favicon 并验证本地与 GitHub Pages 构建路径。
4. 用 100、1,000、5,000 条数据进行视觉、交互和性能回归。
5. 更新 README 的 V1.0.1 记录、发布说明与验收清单，发布 `v1.0.1`。

## 测试与发布门槛

- 单元测试：空间比例、坐标变换、颜色生成、语言聚合。
- E2E：搜索并聚焦在缩放空间中的项目；展开图例并验证语言条目。
- 手动检查：Chrome、Firefox、Safari/WebKit 的 favicon；100/1,000/5,000 条数据的密度与相机体验。
- 性能检查：5,000 条数据下保持与 V1.0.0 相同的画质降级能力，无持续性卡顿。

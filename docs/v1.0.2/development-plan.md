## 目标

解决生产环境首次进入时星体颜色未稳定呈现的问题，并缩短大规模数据采集的无效等待时间；整个过程保持可复现、无重复 Repository，并严格遵守 GitHub API 限额。

本版本不改变数据来源、筛选标准、评分规则或最终数据 Schema。

## 范围

### 1. 首次进入时的星体颜色稳定性

**现状与判断**：页面启动时，`useUniverseData` 先将 180 个演示星传入 Three.js Canvas，再异步替换为真实 Universe。`Instances` 的实例数、颜色和几何缓冲区会在 Canvas 已就绪后发生替换；这会制造首次挂载的 GPU 属性同步窗口。现网页面“首次缺少颜色、刷新后恢复”的现象与此时序一致，但须在生产构建和真实浏览器中复现后作为根因确认。

**方案**：

- 数据加载期间仅显示加载状态，不用演示星先挂载生产 Canvas。
- 只有真实 Universe 校验成功后才创建 Repository Stars；请求失败时才挂载确定性的演示 Universe 作为明确降级。
- 用 `generatedAt + total` 作为场景数据版本键，在数据源切换时重建实例化星体及其 GPU 颜色属性，避免旧缓冲区复用。
- 将“场景 Canvas 已创建”和“当前 Universe 已完成挂载”区分；只有两者完成才移除加载遮罩。
- 对 Universe JSON 请求增加明确的缓存策略和可诊断错误信息；同时在项目级 Pages 路径下验证请求地址。

**验收**：

- 清空浏览器缓存后的首次访问、普通刷新和硬刷新都能直接看见与语言匹配的星体颜色。
- 网络慢速模拟下，用户只会先看到加载状态，不会短暂看到错误颜色或空白星体。
- Chrome、Firefox、Safari/WebKit 各完成一次首次访问验证。
- GitHub Pages 生产构建可正常请求 `/GitGalaxy/data/universe.json`。

### 2. Collector 并发调度与无重复聚合

**现状**：Collector 目前按“查询 → 页码”双层循环串行请求，任意一个请求完成后才发送下一个。固定 2.1 秒全局间隔虽然接近 Search API 的节奏，但语言查询与全局 Star 区间会返回重叠候选，造成重复网络请求和无效等待。

**原则**：

- 并发不等于无上限请求。GitHub REST Search 有独立额度，且每个请求的 `x-ratelimit-*` 响应头才是实时依据；不能以更多并发绕过限制。[GitHub API rate-limit documentation](https://docs.github.com/en/rest/rate-limit/rate-limit)
- 并行任务只能返回候选 Repository，只有一个集中式聚合器可以去重、评分、选择并原子写入 `universe.json`。
- Repository ID 是唯一性依据；完成顺序不得影响最终选集、排序或坐标。

**方案**：

- 将搜索拆为带唯一任务 ID 的查询页任务；同一查询的下一页仅在上一页满页时加入队列，不同查询可由受限 worker pool 并行处理。
- 使用共享的自适应限流器，而不是每个 worker 各自 sleep：读取每次响应的 `x-ratelimit-remaining`、`x-ratelimit-reset` 与 `retry-after`；按剩余额度调节发放速率，遇到 403/429 统一暂停。
- 默认 worker 数设为保守值（例如 4），并暴露受限配置项；吞吐上限始终由共享限流器控制。
- 重构查询规划为互斥的 Star 区间和语言分区，尽量减少源头重叠；仍保留最终 ID 去重以防 GitHub 搜索索引变化或查询边界异常。
- 聚合器在每个响应到达时使用 `Map<repository.id, repository>` 覆盖合并；所有任务结束或已满足“唯一且符合资格的候选池”门槛后，再统一过滤、评分、语言均衡选择和生成 Universe。
- 达到目标候选池并满足语言覆盖后停止未开始的冗余任务；不并行写文件，继续保留单次原子写入。
- 输出可审计统计：请求数、原始条目数、唯一 ID 数、重复条目数、每类查询命中数、限流等待时间与最终选中数。

**验收**：

- 并发乱序返回、同一 Repository 出现在多个任务中时，最终 `universe.json` 仍无重复 ID。
- 同一组模拟响应在串行和并发模式下生成相同的 Repository ID 集、排序和稳定坐标。
- 所有 HTTP 请求总量和速率均遵守共享限流器；403/429 不会引发并发重试风暴。
- 5,000 条采集相较 V1.0.1 基线减少无效重复请求，并输出可比较的耗时与统计。
- 请求失败不会覆盖上一份有效 `universe.json`。

## 实施顺序

1. 为真实数据加载状态与实例化星体数据版本键编写回归测试，复现并修复首屏颜色问题。
2. 引入 Collector 任务队列、共享限流器和集中式 `Map` 聚合器；先保留现有查询逻辑以验证正确性。
3. 将查询改造为尽可能互斥的任务分区，添加早停条件和运行统计。
4. 使用可控的 mock API 覆盖乱序、重复、限流、重试和失败场景。
5. 在 100、1,000、5,000 条目标下测量时间、唯一率和结果质量；完成 GitHub Pages 首次访问回归。
6. 更新发布说明、验收清单和 README，发布 `v1.0.2`。

## 非目标

- 不通过多个 Token 或规避 GitHub 限流提高速度。
- 不让每个 worker 独立筛选、评分或写入部分数据。
- 不为了并发而放弃现有的原子写入、失败保护和坐标稳定性。
- 不更换为数据库、常驻后端或引入新的产品交互。
